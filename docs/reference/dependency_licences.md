## MPL-2.0 packages and why they are acceptable

| Package | Version | Licence | Role |
|---|---|---|---|
| `hypothesis` | 6.168.0 | MPL-2.0 | **test-only** (dev dependency group), never shipped or imported at inference |
| `certifi` | 2026.7.22 | MPL-2.0 | CA bundle, pulled in by `requests`; used only by `acis fetch` |
| `pathspec` | 1.1.1 | MPL-2.0 | transitive (packaging tooling) |
| `orjson` | 3.12.0 | MPL-2.0 AND (Apache-2.0 OR MIT) | fast JSON; dual-licensed, we take Apache-2.0/MIT |
| `tqdm` | 4.70.1 | MPL-2.0 AND MIT | progress bars; dual-licensed, we take MIT |

MPL-2.0 is file-level copyleft: it obliges publication of modifications **to those files**, which we do not make.
No package requires the project itself to change licence.

`acis` itself shows as `UNKNOWN` because `pyproject.toml` declares no `license` field yet — an owner decision
(the repository licence choice), not a dependency problem.

## Model licences

No model weights are part of the locked environment. The encoder radar (G0.4) audits model licences separately:
permissive only (Apache-2.0 / MIT / BSD), safetensors, no `trust_remote_code`, no API — D4 and
`configs/models/*.yaml`. Non-permissive encoders may be *measured* as reference and never shipped (spec 02 §3).
