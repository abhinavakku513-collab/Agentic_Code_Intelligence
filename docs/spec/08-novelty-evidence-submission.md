# 08 · Innovation proof, accuracy escalation, Samsung-criteria pre-flight, submission pack

Authority: subordinate to `CLAUDE.md` §8b, §9–§10. Purpose: turn "win the hackathon" into checkable obligations. Nothing here is an accuracy claim; every number in any deliverable must cite `[ledger:<run_id>]` (INV-14).

## 1. Principle
Novelty is demonstrated, not asserted. Each innovation has a mechanism, a **falsifiable proof obligation** and a place where the judges see it. A claim whose proof fails is deleted from README, PPT and demo (`/evidence-pack` enforces this). Comparisons are only against baselines we ran (ladder B0–B10) or third-party numbers labelled `[R]`; no "state-of-the-art" wording.

## 3. Accuracy escalation protocol (no compromise inside the resource envelope)
Purpose: keep improving P0 accuracy without breaching the envelope (≤ ~1B params, CPU-only inference, cold pass ≤ SLO) or integrity. After the P0 freeze candidate (Phase 5) — or earlier if OOF-pool NDCG@10 is below the owner's target `T` in `configs/targets.yaml` (set by the owner after seeing G0.5 zero-shot numbers) — work these levers **in order**; each is a gated experiment (paired bootstrap; threshold +0.5 pt with CI lower bound > 0; ties → cheaper, G-R; cap 12 trials per lever; log every trial):
| # | Lever | Entry condition / note |
|---|---|---|
| L1 | Best **frozen** encoder (G-M bake-off on all 5,000 TRAIN queries; non-permissive models measured as reference only) | always — the ordering follows the size of the lever [R] |
| L2 | **Adaptation** (G3) on ≤ 2 encoders: LoRA on decontaminated pairs, alternate solutions as positives, false-negative-filtered hard negatives, α-interpolation; small search over rank, τ, negatives | skip if no GPU (O-09); frozen fallback; must pass G-OOD |
| L2b | Optional **distillation** of an offline larger teacher into a ≤ 0.3B student | if size/time scoring bites and the student passes G-M/G3 |
| L3 | Per-route prep sweeps (G1): instruction T1–T3, views V0/V1/V2, lengths 512/1024/2048 | on the adapted encoder, OOF |
| L4 | Hard-negative refinement: re-mining, false-negative-filter ablation | after L2 |
| L5 | BM25 tokeniser/params (E8) and bridge features (G2) | headroom says lexical/bridge cues are missed |
| L6 | PRF second pass (G4) | recall@100 high but rank@1 low |
| L7 | LTR feature expansion **driven by failure buckets** (confusers, truncation, duplicates) — add a feature only if it repairs a bucket | after L5/L6; group dropout stays on |
| L8 | Query-view ensembling (V2 mean or score-level max) | cost ≤ ×1.3 encode |
| L9 | Corpus-only doc–doc centrality feature **E-HUB-C** (computed at index time from corpus vectors only) | must pass `eval-integrity-auditor`: no query-bank statistics, no train-doc detection, D1 unchanged |
| L10 | Second encoder ensemble (E-SECOND) | only if ≥ +1.0 pt at ≤ +60 % cold time (G-R); else dropped |
| L11 | Numeric-profile optimisation (G6) to recover time budget for L8/L10 | after the L10 decision |
**Headroom analysis (guides the order)**: Recall@{1,10,50,100,200} of dense and of the union; oracle NDCG@10 if the gold were perfectly reranked within top-K; failure buckets F1 recall failure · F2 ranking failure · F3 confuser · F4 truncation · F5 parse/tokenisation · F6 duplicates. Recall failures → L1–L4, L10; ranking failures → L5–L9. **Stop rule**: stop when the next lever's headroom is < 0.5 pt or the envelope is exhausted; record the stop in an ADR.
**Forbidden accelerators** (never, however large the gain): train-doc filters/priors, transductive assignment over the query batch, reference-query-bank normalisation, tuning on TEST, external contest corpora (overlap with APPS-test cannot be ruled out cheaply).
