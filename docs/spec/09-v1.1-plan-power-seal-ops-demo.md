## 2. Gate power (why DEV-H alone is not enough)
Rule stays (paired bootstrap, Δ ≥ +0.5 pt **and** CI lower bound > 0). Problem: at n ≈ 1,000 the CI half-width is ≈ 1 pt, so the rule effectively demands Δ ≳ 1 pt. Simulation [E] (per-query paired ΔNDCG@10 SD ≈ 0.16 — 12 % of queries move by ±0.45; re-estimate from real runs):
| true gain | accept prob., n = 1,000 (DEV-H) | accept prob., n = 5,000 |
|---|---|---|
| +0.5 pt | 17 % | 51 % |
| +0.75 pt | 34 % | 87 % |
| +1.0 pt | 53 % | 99 % |
| +1.5 pt | 86 % | 100 % |
**Adopted rule:** (a) gates on components that **fit nothing** (G-M, G1, G2 non-learned parts, G4, prompt/view/length sweeps) use **all 5,000 TRAIN queries**; (b) anything trained (LoRA, LTR, PMI) is judged on **5-fold OOF over all 5,000**, never in-sample; (c) DEV-H (F4) becomes a **once-per-milestone confirmation** with a touch counter, not the decision set; (d) G-AB uses the OOF pool, otherwise Mode B wins by default whenever Mode A's gain is < ~1 pt.

## 3. Physical seal (hooks are speed-bumps, not a boundary — proven by `tests/security/test_guard_hook.py` GAP rows)
1. TEST qrels live **outside the repo tree**: `~/.acis-sealed/` (or another OS user/container). `settings.json` denies Read/Edit there.
2. The dev environment never downloads TEST qrels: dev tasks load `split="train"` only. The **official run alone** uses `HF_HOME=~/.acis-sealed/hf HF_DATASETS_CACHE=~/.acis-sealed/hf/datasets`, so mteb's TEST label files physically land in the sealed area.
3. `acis eval official` is run **by the owner in a terminal** (or through an `ask`-gated command — see settings.json); Claude reads only the resulting ledger row and `verify-submission` output.
4. Reword N3/INV-8 in every document: "TEST labels are kept outside the working tree and touched only at ledgered release candidates; hooks catch accidental access" — not "provably sealed".

## 4. Spec corrections (each would otherwise make a gatekeeper fail or Claude improvise)
- INV-10 / spec 03 §2.6: return **`min(top_k, len(corpus))`** finite, strictly decreasing entries (the 500-doc fixture and the toy G0.1 corpus cannot have 1,000).
- TEST budget: RC0 ×1 + RC1 ×2 + contingency ×2 = 5; **the 6th is the post-hoc clean-pool score** — write it down (CLAUDE.md §4, STATUS.md).
- **G0.6** is cited in CLAUDE.md §9 but undefined: define it as "guard/hook tests + canary green".
- D1 exposure diagnostic must not use TEST queries as a gate input (conflicts with INV-3's spirit): compute the analogue on the **held-out fold** (share of held-out-query top-10 slots occupied by docs the adapted model trained on, vs the base model and vs the prior).
- `acis` config paths (`configs/official.yaml`) resolve relative to the repo root, not the CWD (a judge may run from anywhere).

## 5. Long jobs
Anything > ~10 min (bake-off, embedding pass, adaptation export, **official cold run**) runs through `scripts/run_detached.sh` / `scripts/job_status.sh` or in the owner's terminal. Dev jobs are resumable (CAS makes indexing resumable); the official cold run must finish uninterrupted so that `evaluation_time` stays honest. GPU work: docs/GPU_HANDOFF.md.

## 6. Hands-on runbook spec (Track B; the hands-on stage picks the winner among screened finalists)
**Scope:** PPT and demo video are made by the **owner**, not by Claude Code (see `docs/submission/OWNER_HANDOFF.md`). Claude Code delivers `make demo`, a runbook and ledger-generated evidence files. Queries are **never scripted**: every act starts from a free-text box; example chips are optional (docs/spec/10 Q8).
| Panel / act | What the judge sees | Acceptance |
|---|---|---|
| Act 1 P0 | paste ANY query — an APPS-style statement, a one-line question, an identifier, a code fragment → top-3 with exact source, per-channel ranks, **contract cues** linking statement spans to code spans, confidence band, stage-timing bar | p95 encode+search per spec 02 §7 on the declared host |
| Channel toggle | same query with BM25-only / frozen dense / adapted / full pipeline, numbers from the ledger | every number carries `[ledger:<id>]` |
| Resource scorecard | params, model MB, peak RSS, cold/warm time, latency, GPU = none | matches manifest |
| Act 2 P1 — **commit stream** | `scripts/demo/commit_stream.py` replays versions at 1 per N seconds ("new commits every minute", PDF p.2); live freshness gauge (commit → searchable), units re-embedded, snapshot states, then rollback and a `kill -9` mid-build with recovery | p95 update time for ≤ 10 changed units published with hardware; leak counter 0 |
| Act 3 Bonus | `version=all` grouped lineages with timeline/diffs vs `flat=true`; duplicate counter; wrong-merge audit | Evolution-NDCG@10 > flat, CI > 0 |

Owner-side: slides and video use `docs/submission/*` figures/tables; every number cites a ledger id (INV-14).
