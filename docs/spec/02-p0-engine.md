# 02 · P0 engine specification

Authority: subordinate to `CLAUDE.md` (D1–D9, D15, INV-3/4/6/10). Numbers marked [E] are targets to be replaced by measurements; nothing here is an accuracy claim.

## 1. What is retrieved
Query = a full APPS problem statement (prose + input/output spec + examples, ≈420 tokens on average, up to ≈1.5k). Relevance unit = one whole Python program (mean ≈190 tokens, heavy tail). Exactly one relevant doc per query; 8,765 docs at test. Consequence: score is a function of one rank; whether the encoder has learned problem→solution pairs dominates; lexical overlap is weak (prose vs code).

## 2. Representations
**Query (`prep.query`)** — `q1`: Unicode NFKC, `\r\n→\n`, strip trailing spaces, cap blank-line runs at 1, drop control chars. Nothing else for the dense view (raw statements are what encoders were trained on). Instruction prefix in the encoder's documented format; for Qwen3-style: `Instruct: {TASK}\nQuery: {q1}` with TASK ∈ {T1 "Given a programming problem statement, retrieve the Python solution program that solves it", T2 "Given a competitive programming problem description, retrieve the code that implements a correct solution", T3 "Given a query, retrieve relevant code"}; per-model formats live in `configs/models/<name>.yaml`. Segmentation (regex on `-----Input-----` / `-----Output-----` / `-----Examples-----` / `-----Note-----` and generic `Input`/`Output`/`Example` headers [I: markers confirmed in G0.2]) → `{statement, io_spec, examples, note}`; markers are hints only — absence or failure falls back to the whole text, never an error (INV-15). Views: **V0** full text (default) · **V1** statement+io_spec without examples/note (cheaper) · **V2** mean of V0 and V1 embeddings. Truncation: head 768 + tail 256 tokens (sweep 512/1024/2048). **Per route (INV-15, spec 10 Q1)**: `statement_like` uses the G1 winner; every other route uses the generic T3 (or no instruction when the encoder has none); G1 runs per route on that route's dev set. G1 chooses task string × view × length by accuracy, ties → cheaper.
**Lexical view** — prose to lowercase words; fold `10^9+7`, `10^{9}+7`, `1e9+7` → `1000000007`; strip LaTeX macros; keep numbers and quoted literals.

**Document (`prep.doc`)** — `d1`: strip BOM/`\r`/trailing whitespace, keep tabs; no comment stripping unless E4 shows a gain; `title` empty on CoIR, else `title + " " + text` (mteb convention). Dense text: head 768 + tail 256 tokens. Full text always goes to BM25 and the feature extractor, so truncation only costs the dense channel.
**Code-aware BM25 (`lexical`)** — doc tokeniser splits snake/camel/digit boundaries, lowercases, keeps Python keywords/builtins that carry algorithm hints (`sorted`, `heapq`, `deque`, `defaultdict`, `bisect`, `gcd`), keeps string literals and folded numeric constants, maps operators to tokens (`%→op_mod`, `//→op_floordiv`, `**→op_pow`, `<<→op_shl`). bm25s per snapshot (exact per-snapshot statistics); `k1∈{0.9,1.2,1.5}`, `b∈{0.4,0.75,0.9}` tuned on the OOF pool (two parameters, negligible optimism).
**Features (`features`)** — `ast`-only, parse-only, sandboxed: imports, input-parsing shape (`input()` count, `sys.stdin`, `map(int, …split())`, test-case loop), output literals, numeric constants, recursion/`lru_cache`, data-structure idioms, parse success. Failure ⇒ NaN (LightGBM handles it); the doc stays retrievable by dense + lexical. Query-side extractors are generic (numeric-literal and quoted-string overlap, input-shape cues) — no fixed list of moduli, phrases or headers (INV-15).

## 3. Encoder policy (D4)
- **Radar (Phase 0, G0.4)** — re-read the live MTEB(Code)/CoIR leaderboards for models ≤ ~1B params; keep only permissive licence (Apache-2.0/MIT/BSD), safetensors, no `trust_remote_code`, no API. Seed shortlist [R]: Qwen3-Embedding-0.6B (seed), gte-modernbert-base 149M, granite-embedding-english-r2 149M / small-r2 47M, CodeRankEmbed 137M (custom code → vendor + audit, else skip), jina-embeddings-v5-text small/nano and other 2026 releases (licence to verify). Baselines/reference only: BGE-M3, jina-code-embeddings (CC-BY-NC), Qwen3-Embedding-4B (upper bound, never shipped). Non-permissive encoders are still **measured** (reference for the gap the permissive-only rule may cost); `docs/official/ORGANIZER_QA.md` Q5 asks whether they are acceptable.
- **Selection (G-M)** — measure frozen zero-shot on **all 5,000 TRAIN queries** (nothing is fitted, spec 09 §2): NDCG@10, MRR@10, Recall@100, tokens/s (fp32, bf16), RSS, projected cold time. `best = argmax NDCG@10`; eligible = candidates within **1.0 pt** (`size_tolerance_pts`, `configs/gates/G-M.yaml`; **3.0 pt** when the best candidate's projected cold pass exceeds 2 h on the declared host [JUDGMENT]) of best under the cold-run SLO; choose the fewest parameters (tie → higher NDCG). Hard envelope: ≤ ~1B parameters, CPU-capable, no API. After Phase 3 (adaptation), re-run over {frozen, adapted} variants.
- **Numeric profiles** — `cpu-fp32` (reference; the official JSON) · `cpu-bf16` · `cpu-int8` (ONNX Runtime dynamic quantisation) · `gpu-fp16` (bulk embedding/training only). Cache keys include the profile. A non-reference profile serves only after G6 (top-10 overlap ≥ 99 %, paired ΔNDCG@10 ≥ −0.3); GPU vectors enter the shared cache only after cosine ≥ 0.999 on a 1 % sample. Smaller/faster profile that passes G6 wins (G-R).
- **Runtime** — pooling/normalisation per model card (Qwen3: last-token, left-padded, L2); length-sorted token-budget batching (~16k tokens/batch [E]); intra-op threads = physical cores; one inference process; `torch.inference_mode`; memory-mapped safetensors; model pinned by commit SHA + per-file SHA-256; `HF_HUB_OFFLINE=1`.
- **Cache keys** — doc/unit vector: `sha256(model_fingerprint ‖ profile ‖ prep_hash ‖ embed_key)`; query vector adds `prompt_hash`; `model_fingerprint` = hash of weights + tokenizer + adapter. Audit mode recomputes 1 % of hits (cosine ≥ 0.9999).

## 4. Per-query pipeline (batch-invariant; roles are fixed)
| Stage | Role | Detail |
|---|---|---|
| 1 route | fallback-safe | routing v1.1 (spec 10 §4): `statement_like` iff the query-side OOD score (mean cosine to its k nearest TRAIN-query embeddings; never offsets a document score) ≥ τ_ood **and** bridge-feature availability ≥ ρ; everything else and any routing failure → `generic`. Chooses instruction, views, ranker and confidence calibration; dense + lexical always run |
| 2 encode | **primary** | per-route instruction + view → vector (the only expensive step) |
| 3 dense | **primary** | exact `q·Dᵀ` over all docs; top-100 kept, whole ranking kept for the tail |
| 4 lexical | auxiliary (G2) | BM25 top-30 |
| 5 PRF | optional (G4, default off) | `q' = norm(q + α·Σ wᵢdᵢ)`, m∈{1,3}, α∈{0.2,0.4}; second-pass score/rank become LTR features; uses only that query's own results |
| 6 union | – | dense top-100 ∪ BM25 top-30, cap 100 (RRF pre-cut if larger) |
| 7 features | – | Appendix A below |
| 8 rank | **primary** (G5) | `statement_like`: LightGBM LambdaRank, abstaining (dense order) when fewer than ρ of the feature groups are available; `generic`: weighted fusion tuned on REG data. Fallbacks: weighted fusion → dense-only → BM25-only (each a counted degradation; strict aborts) |
| 9 tail | – | remaining dense order to rank 1,000 |
| 10 compose | – | Mode A: rank-derived scores `(1001−rank)/1000`; exact duplicates adjacent by corpus ordinal; exactly `min(top_k, N)` entries |
| 11 confidence | routing signal only | LTR margin, dense/lexical agreement, PRF stability, candidate entropy → isotonic (out-of-fold) → high/medium/low; never reorders |

**LTR** — groups = query with ≤100 candidates (a missing positive contributes negatives only; recall failures are not hidden); ~28 features from out-of-fold dense scores; `objective=lambdarank`, `lambdarank_truncation_level=20`, `eval_at=[10]`, 300–600 trees, `num_leaves=15`, `learning_rate=0.05`, `min_data_in_leaf=50`, `feature_fraction=0.8`, monotone non-decreasing in `cos` and `bm25`; **feature-group dropout** (≈25 % masking per group) during training so no single extractor is load-bearing (INV-15); 5-seed variance reported; model stored as LightGBM text. Serving ≈ ms [E].
**Appendix A features** (no IDs, no split membership): Dense `cos, rank_dense, z_cos, gap_top1, q_margin, cos_prf, rank_prf` · Lexical `bm25, rank_lex, bm25_norm, rrf_prior` · Bridge (generic, NaN when absent, group-masked in training) `out_literal_recall, const_jaccard, numeric_literal_overlap, io_shape_compat, tc_loop_expected, bridge_hits/bridge_pmi (support ≥ 8 distinct problems; cuttable)` · Meta `log_doc_tokens, log_q_tokens, len_ratio, is_truncated, parse_ok, dup_cluster_size (corpus-only), stuffing_score`.

## 5. Long code / long documents — the explicit answer
- **P0 (whole-program documents, mean ≈190 tokens)**: one document-level vector; head+tail truncation (768+256) bounds cost; BM25 and features see the full text. Ablation grid {256, 512, 1024, 2048} (G1). Docs beyond the cap are rare [I]; **E-LONG** (only if G0.2 shows a material long tail): 512-token windows, stride 384, doc score = `max(doc-vector score, max window score)` (MaxP), enabled only if ΔNDCG@10 ≥ +0.5 pt.
- **Propagation**: windows never appear in outputs; only document ids are ranked, and each window score maps back to its parent id. The same rule serves version snapshots (unit = snippet) and function-level units (unit score = max over its windows).
- **Rejected**: multi-vector/late-interaction (encoders are not trained for it), hierarchical retrieval (8.8k docs — exact search is microseconds), semantic-window pipelines for P0 (no accuracy case; costs runtime).
- Queries longer than the cap use head+tail; V1 (no examples) is the cheaper alternative chosen by G1.

## 6. Adaptation (D7, gate G3)
Data: APPS-train pairs only, after MinHash decontamination (5-gram, 128 perms, drop Jaccard ≥ 0.8 vs TEST inputs; log the drop list; exact dedup inside TRAIN). Where the source record has ≥ 2 solutions, train on a different one than the corpus copy [U: check in G0.2]. Objective InfoNCE (τ ∈ {0.02, 0.05}); ≥ 64 queries/step, 1 positive + 7 mined hard negatives + in-batch negatives, no two positives of one problem in a batch; hard negatives from the current model's top-50 with false-negative filter (cos(pos,cand) > 0.92, or token Jaccard > 0.8, or ≥ 70 % statement 5-gram overlap), re-mined after epoch 1 inside the training fold only. LoRA r∈{16,32,64} on attention + MLP, lr 1e-4 cosine, 2–3 epochs, bf16 on A100/L4-class GPUs (fp16 + loss scaling on a T4, which has no bf16), fixed seed, then merged to safetensors as `θ = θ_base + α·Δ` with α tuned on APPS OOF **and** REG/G-OOD (WiSE-FT-style interpolation, zero inference cost, protects generality). Optional: distil an offline larger teacher into a ≤ 0.3B student (attacks the size/time scoring; only if it passes G-M/G3). Compute plan and hand-off: `docs/GPU_HANDOFF.md` (cheaper variants: 2-fold, 3 negatives, max length 512, ≤ 2 epochs). 25 % replay from general code-retrieval pairs (decontaminated vs REG). K-fold cross-fitting over **all 5,000** TRAIN pairs (K = 5 if the GPU budget allows, else 2: train on one half, score the other, both directions) yields out-of-fold vectors for LTR and the G3 decision; the shipped model is a refit on all 5,000 with frozen hyper-parameters (OOF estimate reported; DEV-H confirms once per milestone). At most **two** encoders are adapted (the seed and the next-smaller within 6 pts). Provenance (scripts, manifest, seeds, env lock) ships in the Release.
**Exposure controls**: D1 diagnostic on a **held-out fold** (share of held-out-query top-10 slots occupied by documents the adapted model trained on, vs the base model and vs the corpus prior; flag if it deviates > 10 pts) — never computed on TEST queries (INV-3); no train-doc detector of any kind; PMI bridge table needs ≥ 8 distinct problems per association; clean-pool score (TRAIN-corpus docs removed) reported once post hoc.

## 6b. Query understanding and fallbacks
Segmentation or router failure ⇒ V0 + all channels (never remove the dense+lexical baseline). Empty query ⇒ `InvalidInput`. Query > 16k chars ⇒ head+tail with `query_truncated=true`. The `generic` route (short questions, identifiers, code fragments, mixed text) uses weighted fusion with an exact identifier channel first for identifier-like queries. It is **first-class**: gated by G-OOD (spec 10 §5) and tuned on REG data (human-written queries), never on APPS-derived stubs.

## 7. Resource budgets, tiers, cold start (all [E] until measured)
| Item | Target |
|---|---|
| Retrieval core (matmul + BM25 + LTR + verify), N≈9k | p95 ≤ 15 ms |
| Encode: long statement (≈420 tok) | p95 ≤ 1.5 s fp32 · ≤ 0.8 s if bf16/int8 passes G6 (8 cores) |
| Encode: short query (≈30 tok) | p95 ≤ 150 ms; repeated query (cache) ≤ 5 ms |
| Model cold load / snapshot open | ≤ 5 s (mmap) / ≤ 1 s at 100k units |
| Official cold pass (index 8,765 docs + 3,765 queries ≈ 3M tokens) | SLO ≤ 4 h on T-rec CPU; ≈1.4–8 h for a 0.6B encoder depending on sustained GFLOPS — **measure** (G0.3); a slower result triggers the D4 rule toward a smaller model |
| Memory | fp32 0.6B model ≈ 2.4 GB (bf16 ≈ 1.2 GB); doc matrix (8,765×1,024 fp32) ≈ 36 MB; peak ≈ 4–5 GB |
Tiers: **T-min** 4 cores/8 GB (bf16/int8 or ≤150M encoder; long official pass) · **T-rec** 8+ cores/16 GB (reference host) · **T-gpu** optional, offline only. Cold vs warm are always reported separately; cold = fresh process, empty caches, model load included.
